Choose the comparison

Pair scoring assigns a model score to a receptor together with a peptide–MHC target. Start with a concrete question, such as comparing candidate peptides for a fixed receptor and HLA context. Check the model documentation to establish which comparisons its score supports.

This task produces pair scores. If your question concerns the predicted three-dimensional arrangement, use structure prediction.

Prepare the pairs

Use the scoring notebook’s input format. Each pair needs the receptor alpha and beta chains, peptide and HLA context, with the sequence preparation required by DecoderTCR-Fold. Supply one amino-acid sequence per component, without preparing a multiple sequence alignment. Keep a unique pair identifier so the output can be traced back to its input.

Check chain pairing, HLA identity and sequence completeness before running the model. If an input requires reconstruction from gene annotations, retain the original annotations and the reconstructed sequences.

Run pair scoring

  1. Run the supplied example. Check that the notebook loads the intended DecoderTCR-Fold version and completes its scoring workflow.
  2. Inspect your input table. Review pair identifiers and any validation messages.
  3. Score a small set. Use the notebook’s documented settings and confirm that each returned row maps to the expected pair.
  4. Continue with the full comparison. Keep the settings consistent and preserve failed rows with their messages.

Interpret the scores

Read the score definition before sorting the output: what quantity does it represent, which direction indicates stronger predicted interaction, and across which inputs can it be compared? Use the model card and scoring documentation to answer those questions for the version you ran.

Model scores and experimental measurements

A pair score is a model output. Interpret it using the model’s score definition and evaluation. Binding affinity and T-cell activation require experimental measurement.

DecoderTCR-Fold scores and DecoderTCR sequence PLL come from different model workflows. Keep their names and settings with the results, and evaluate each on its own terms.

Save the comparison

Keep the score table, failed rows and original inputs with the notebook. Record the model version, notebook revision, hardware and scoring settings. Download the result files before ending the Colab session; its runtime storage is temporary.
