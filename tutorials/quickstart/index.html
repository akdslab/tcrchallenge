About this tutorial

Code is adapted from the public sequence API at 3e3d988. Run the notebook to generate results with your chosen checkpoint and device. Input contract.

Eight fields describe one pair

Supply the V and J gene names and CDR3 amino-acid sequence for each receptor chain. Then supply an HLA allele identifier and the peptide sequence to score. Look up an unfamiliar term.

The public README example. This example does not establish whether the pair binds.
FieldWhat you supplyExample
travAlpha-chain V geneTRAV21
trajAlpha-chain J geneTRAJ6
cdr3aAlpha-chain CDR3 sequenceCAVRPGGAGPFFVVF
trbvBeta-chain V geneTRBV7-9
trbjBeta-chain J geneTRBJ2-7
cdr3bBeta-chain CDR3 sequenceCASSLGQAYEQYF
hlaHLA allele identifierHLA-B*27:05
peptidePeptide amino-acid sequenceLRVMMLAPF

The components API reconstructs the longer receptor chains and looks up the HLA sequence. An allele name is a lookup key; do not pass it to a full-sequence API as an amino-acid sequence. How reconstruction works.

Run one example

Save this code as score_pair.py in the source checkout. It returns a table with a model-specific pll_ column and reconstruction diagnostics.

Python · adapted from the public API
import DecoderTCR as dt

model = "DecoderTCR-ESMC_300M"
pair = {
    "trav": "TRAV21", "traj": "TRAJ6", "cdr3a": "CAVRPGGAGPFFVVF",
    "trbv": "TRBV7-9", "trbj": "TRBJ2-7", "cdr3b": "CASSLGQAYEQYF",
    "hla": "HLA-B*27:05", "peptide": "LRVMMLAPF",
}
result = dt.score_from_components(pair, model=model, device="cpu")
print(result[["name", "ok", "tcr_reason", "hla_reason", f"pll_{model}"]])

Read the result in the right order

Was the pair reconstructed?

Start with ok. If false, read tcr_reason and hla_reason. A missing score is missing information, not evidence of non-binding.

Which model produced the score?

Keep the checkpoint, source revision, device and peptide length with your result. The score-column name identifies the checkpoint used here.

What does the score mean?

PLL is the average log-probability of the true amino acids after the whole peptide is masked. A higher score means the model assigns the peptide higher likelihood in the supplied receptor and HLA context. It does not give a probability of binding.

A ranking score is not a binding probability

PLL does not give a percentage chance of binding, a measured affinity or experimental confirmation. Exponentiating it does not make it a binding probability. Define the candidate set you want to rank and the experiment you would use to test the predictions.

Try your own table

A CSV uses the same fields. The optional name identifies each row; make names unique. Keep supplied label values separate from model scores. Start with a small subset.

Python · CPU batch example
import DecoderTCR as dt
import pandas as pd

pairs = pd.read_csv("pairs.csv", keep_default_na=False)
scored = dt.score_from_components(
    pairs, model="DecoderTCR-ESMC_300M", device="cpu"
)
print(f"{int(scored['ok'].sum())}/{len(scored)} rows reconstructed")
print(scored.loc[~scored["ok"], ["name", "tcr_reason", "hla_reason"]])
scored.to_csv("scored.csv", index=False)

Save all rows, including failures. The notebook adds a run record alongside the CSV and demonstrates a small subset of the public sample data.
