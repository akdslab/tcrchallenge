Setup guide

Set up the TCR-Workbench CLI

TCR-Workbench is a command-line tool for running DecoderTCR on your own computer. Install it by hand with a few commands, or let a coding assistant do it for you using the bundled setup skill.

Before you begin

TCR-Workbench is a command-line (CLI) tool that runs DecoderTCR, the sequence model, on your own computer and writes offline HTML reports. This guide installs it from scratch. You can install it by hand with a few copy-paste commands — no programming needed — or let a coding assistant do it for you. The assistant is optional but helpful, and the repository ships a setup skill it can follow so it knows exactly which options to choose.

You will need a computer where you can install software, an internet connection (the model weights download the first time you score), and a few gigabytes of free disk space. Use the public example for your first run.

What is a terminal, and where do I paste commands?

A terminal is a window where you type commands and press Enter to run them. On a Mac, open Terminal from Spotlight. On Windows, open PowerShell from the Start menu. On Linux, open your Terminal application.

To move into a folder, type cd followed by its full path in quotation marks, then press Enter. You can often drag the folder into the terminal to insert its path. cd means “change directory”. Run pwd on Mac or Linux, or Get-Location in PowerShell, to check the current folder.

Paste blocks labelled Terminal into that window. Paste blocks labelled Message to your assistant into the assistant’s conversation.

What you'll install

  • TCR-Workbench — the command-line tool. You run everything through one launcher, python3 tcr.py, from the folder that holds the code.
  • DecoderTCR — the scientific model that produces the predictions. Its weights are fetched from Hugging Face by default and download automatically the first time you score, not during setup.
  • The bundled setup skill — skills/tcr-workbench-setup inside the repository. A coding assistant reads it and uses it to pick the right options for your computer, install the model and verify the result.

TCR-Workbench runs locally; it does not need a Biohub MCP connection or an internet service beyond the one-time weight download.

1. Get the code

Choose a permanent location first — moving the folder after setup can break saved paths. Clone the repository and enter the folder:

Terminal · Mac, Linux or Windows PowerShell
git clone https://github.com/akdslab/tcr-workbench.git
cd tcr-workbench
python3 --version

The launcher needs Python 3.9 or newer; setup then provisions its own Python 3.12 for the model environment. If python3 --version reports an older version, install a current Python first.

Prefer to download a ZIP instead of using Git?

On github.com/akdslab/tcr-workbench, choose Code → Download ZIP, extract it, and enter the extracted folder in your terminal.

2. Install a coding assistant (optional)

This step is optional but helpful. A coding assistant can run the install for you and explain each step, which is useful if you don't spend much time in a terminal. If you'd rather type a few commands yourself, skip this step and go to install by hand in step 3.

If you do want one, choose the tool you have access to — you only need one. Codex and Claude Code have desktop and terminal options; Gemini CLI runs in a terminal. When asked which folder to open, choose the tcr-workbench folder from step 1.

  2. Sign in with an account that has Claude Code access.
  3. Open the Code tab, select Local, then choose the tcr-workbench folder. Follow any operating-system setup steps in the guide.

For a terminal interface, follow the Claude Code CLI installation guide, open a terminal in tcr-workbench and run claude.

  2. Sign in using an account with Codex access. See the authentication guide for account and API-key options.

For a terminal interface, follow the Codex CLI installation guide, open a terminal in tcr-workbench and run codex.

  2. Open a terminal in tcr-workbench and run the commands below one line at a time.

3. Install TCR-Workbench

There are two ways to install, and both do the same thing: by hand with a few copy-paste commands, or with the coding assistant from step 2. Pick whichever you prefer.

Install by hand

No assistant needed. From the tcr-workbench folder (the one containing tcr.py), choose one command for your computer:

Terminal · choose one
# Mac with an Apple M-series chip
python3 tcr.py setup --device apple

# CPU on Mac or Linux (always works; slower on large models)
python3 tcr.py setup --device cpu

# NVIDIA GPU on Linux (needs working NVIDIA drivers)
python3 tcr.py setup --device gpu

Then confirm the install:

Terminal
python3 tcr.py doctor

Setup installs dependencies and the DecoderTCR package; it does not download a checkpoint. With no internal registry configured, it defaults to the released Hugging Face weights, which are fetched and verified the first time you score. Setup saves your device choice, so later commands do not need the --device flag.

Or let a coding assistant do it

If you installed a coding assistant in step 2, you can skip the commands above and send it this message instead. It will choose the right option for your computer using the bundled setup skill, install the DecoderTCR model package and verify the result:

Message to your assistant · install
Install TCR-Workbench in this folder using the bundled setup skill in
skills/tcr-workbench-setup.
Pick the right option for my computer -- a Mac with an Apple chip, a plain
CPU, or an NVIDIA GPU -- and install the DecoderTCR model.
Then run the built-in check to confirm it is ready.
Tell me what each command does before you run it, and do not analyze any of
my data yet.

The skill installs the dependencies and the DecoderTCR package into a managed environment. It does not download the model weights yet — those arrive from Hugging Face the first time you score. When it finishes, the assistant should report your device, the model (DecoderTCR 300M by default) and a reachable weight source.

Bundled skill: skills/tcr-workbench-setup · installs the CLI

Check: however you installed, run python3 tcr.py doctor (or ask the assistant to) and confirm it reports an installed device and model with no errors.

4. Run your first analysis

Run a profile for a nine-residue peptide in the context of HLA-A*02:01. Ask the assistant, or paste the command yourself from the tcr-workbench folder:

Terminal
python3 tcr.py pmhc-profile --hla 'HLA-A*02:01' --length 9 --out results/first-profile

The first analysis downloads the model weights from Hugging Face (about 1.3 GB for the 300M model) into the tool's own cache, then runs. Later runs reuse the cached weights and are faster. Keep the computer awake during the download. Use a new --out folder for each run, such as results/first-profile-2 when repeating this example.

Behind a CZ Biohub (or other TLS-inspecting) network?

On a network that inspects secure traffic, the first weight download can fail even when the network is otherwise fine. The common fix is to disable Hugging Face's accelerated transfer before scoring:

Terminal
export HF_HUB_DISABLE_XET=1
python3 tcr.py pmhc-profile --hla 'HLA-A*02:01' --length 9 --out results/first-profile

If you still see a certificate error, ask your assistant to follow the “corporate / TLS-inspecting proxy” section of the bundled setup skill, which adds the system certificate bundle.

5. Check the result

Open results/first-profile/report.html in your browser for the amino-acid heatmap, sequence logo and run details. Alongside it:

  • profile.csv — the amino-acid probabilities at each peptide position.
  • pssm.csv — the position-specific scoring matrix.
  • Run details — the checkpoint, device and settings that produced the result.

The motif describes positional preferences the model predicts for this MHC; it is a hypothesis, not a measured binding motif or a probability of binding. Continue to the sequence-model tutorial to score a TCR–pMHC pair and read a PLL score, then try a small table of your own inputs.

If a step fails

“The launcher needs Python 3.9 or newer”

Your system Python is too old. Install Python 3.9+ and reopen the terminal; setup then provisions its own Python 3.12 for the model.

“Apple setup requires macOS on Apple Silicon”

You used --device apple on a computer that is not an Apple M-series Mac. Use --device cpu instead.

“Automatic NVIDIA GPU setup targets Linux”

You used --device gpu outside Linux. On a Mac use --device apple; otherwise use --device cpu.

The weights will not download

The first scoring run needs internet access to Hugging Face. On a TLS-inspecting network (such as CZ Biohub), set export HF_HUB_DISABLE_XET=1 and try again, or ask your assistant to apply the proxy fixes in the bundled setup skill. A public model needs no login; a private or gated one needs a Hugging Face token (export HF_TOKEN=hf_…).

A download fails or the model runs out of memory

If setup or scoring stops with an estimated-memory message, the model is too large for this computer. Use the default 300M model on CPU, or move to a machine with more memory or a GPU. Do not override the memory guard unless you understand the risk.

“DecoderTCR not installed” or “Setup is needed” at analysis time

The model package is missing from the environment. Re-run the install for your device (python3 tcr.py setup --device …), then python3 tcr.py doctor.

The terminal says a command was not found

Reopen the terminal after installing, and make sure you are in the tcr-workbench folder (run python3 tcr.py doctor there). For Gemini CLI permission errors, follow npm’s installation guide.

A row or peptide has no score

Read the reconstruction reason columns and check the V/J gene names, CDR3 sequences and HLA allele. A missing score is not evidence that a pair does not bind.
