Before you begin

A coding assistant can explain a command, prepare an analysis script and help run it. The Biohub MCP server supplies the model instructions and task guides it needs. DecoderTCR and DecoderTCR-Fold are the scientific models that produce predictions.

Steps 1–3 set up the assistant and its Biohub connection. You can then use either model. The structure tutorials run in Google Colab; an optional first sequence-model run on your computer follows in steps 4–5.

You will need an internet connection, access to your chosen coding assistant and permission to install software. Use the public example for your first run. A browser chat alone does not give an assistant access to files or programs on your computer; this guide uses a local coding session.

1. Make a project folder

Create a folder named TCR-work somewhere you can find easily, such as Documents. This project folder holds the inputs, scripts and results for your analysis. Open it in your assistant when asked to choose a project.

What is a terminal, and where do I paste commands?

A terminal is a window where you type commands and press Enter to run them. On a Mac, open Terminal from Spotlight. On Windows, open PowerShell from the Start menu. On Linux, open your Terminal application.

To work in your project folder, type cd followed by its full path in quotation marks, then press Enter. You can often drag the folder into the terminal to insert its path. cd means “change directory”. Run pwd on Mac or Linux, or Get-Location in PowerShell, to check the current folder.

Paste blocks labelled Terminal into that window. Paste blocks labelled Message to your assistant into the assistant’s conversation.

2. Install one assistant

Choose the tool you have access to. Codex and Claude Code have desktop and terminal options; Gemini CLI runs in a terminal. You only need one.

OpenAI · Codex
  1. Follow the official desktop app guide to install the app for your computer.
  2. Sign in using an account with Codex access. See the authentication guide for account and API-key options.
  3. Open TCR-work as a local project and start a Codex session in Local mode.

For a terminal interface, follow the Codex CLI installation guide, open a terminal in TCR-work and run codex.

Anthropic · Claude Code
  1. Install the desktop app using the official setup guide.
  2. Sign in with an account that has Claude Code access.
  3. Open the Code tab, select Local, then choose TCR-work as the folder. Follow any operating-system setup steps in the guide.

For a terminal interface, follow the Claude Code CLI installation guide, open a terminal in TCR-work and run claude.

Google · Gemini CLI
  1. Install the current LTS version of Node.js, which includes the npm installer. Reopen your terminal.
  2. Open a terminal in TCR-work and run the commands below one line at a time.
Terminal · Mac, Linux or Windows PowerShell
node --version
npm --version
npm install -g @google/gemini-cli
gemini
  1. Follow the sign-in prompt. Use the official authentication guide for personal, university or company account requirements.

The installation guide lists supported systems and prerequisites.

Message to your assistant · folder check
Show the full path of this project folder and list its files.
Do not install or run a model yet.

Check: the path should be your TCR-work folder. If the assistant only describes how to list files, check that you opened a local coding session.

3. Connect to Biohub MCP

MCP lets the assistant retrieve Biohub’s model instructions and task guides. Add the server using one of the options below, then check that the assistant can read both models’ instructions.

Biohub MCP

Connection details

Server address · launch placeholder. Replace BIOHUB_MCP_SERVER_URL in the examples below with the published Biohub MCP address before running a connection command.

Server address · launch placeholder
BIOHUB_MCP_SERVER_URL

Connection type: Streamable HTTP. Server name: biohub.

Sign-in requirements will be supplied with the server address.

For terminal commands, open a second terminal in TCR-work if your assistant is using the first one. Use the server address shown above. If Biohub requires sign-in, follow its published authentication instructions.

Connect Codex to Biohub
  1. In the desktop app, open Settings → MCP servers → Add server.
  2. Enter biohub as the name, select Streamable HTTP and paste the server address.
  3. Save, then select Restart. If OAuth sign-in is required, select Authenticate.
  4. Enter /mcp in the conversation to check the connection.

With Codex CLI, use:

Terminal · Codex connection
codex mcp add biohub --url "BIOHUB_MCP_SERVER_URL"
codex mcp list

If the server uses OAuth, run codex mcp login biohub. Start a new session after configuring the server. The desktop app and CLI share their MCP configuration.

Official Codex MCP instructions.

Connect Claude Code to Biohub
  1. For the desktop Code tab, add the configuration below to a file named .mcp.json in TCR-work. Your assistant can create the file; ask it to preserve any servers already configured.
  2. Use the server address shown above, save the file and start a new local Code session in this folder.
  3. Enter /mcp to check the connection and complete sign-in if requested.
Project configuration · .mcp.json
{
  "mcpServers": {
    "biohub": {
      "type": "http",
      "url": "BIOHUB_MCP_SERVER_URL"
    }
  }
}

With Claude Code CLI, this command adds the connection instead:

Terminal · Claude Code connection
claude mcp add --transport http biohub "BIOHUB_MCP_SERVER_URL"

Run it from TCR-work, then start a session there. Use /mcp to check status and authenticate when required.

Official Claude Code MCP instructions · Desktop and CLI configuration.

Connect Gemini CLI to Biohub
  1. In a terminal in TCR-work, add the server and list configured connections:
Terminal · Gemini CLI connection
gemini mcp add biohub "BIOHUB_MCP_SERVER_URL" --transport http
gemini mcp list
  1. Start a new Gemini CLI session in the same folder.
  2. Use /mcp list to check the connection. If OAuth sign-in is required, use /mcp auth biohub and follow the browser prompt.

Check that the instructions can be read

Once the server is connected, send:

Message to your assistant · connection check
Read the model instructions available through Biohub MCP for DecoderTCR and DecoderTCR-Fold.
Show the instruction titles or identifiers and their versions, if provided.
List the available task helpers and explain which model fits each task.
Tell me where the model will run and what setup it needs. Do not run an analysis yet.

Check: the response should identify instructions retrieved from Biohub for DecoderTCR and DecoderTCR-Fold, describe the available tasks and explain their computing requirements. A configured server name alone does not show that the instructions were retrieved.

Choose your first tutorial

Open a model tutorial and copy its assistant message. For structure prediction or structure-model pair scoring, continue in Google Colab. Connecting to MCP does not install model weights or supply a GPU; the chosen tutorial covers model setup. The local sequence example below is optional.

4. Try the sequence model locally

Return to your assistant in TCR-work and send the request below. This example selects the 300M checkpoint on CPU, your computer’s main processor. It does not require an NVIDIA GPU, but the model still needs memory and storage. CPU guidance.

Task helper: score_tcr_pmhc · DecoderTCR

Read the helper’s instructions through Biohub MCP, then run it in the environment specified by the guide. You can also follow the notebook step by step.

Message to your assistant
Use Biohub MCP to read the DecoderTCR instructions and the score_tcr_pmhc task guide.
Use the helper interface described there.
Follow https://tcrchallenge.org/tutorials/quickstart/

Check the prerequisites and complete the quick-start setup in a new DecoderTCR subfolder.
Run the public example with the 300M checkpoint on CPU.
Save all rows, errors and run settings; show the output file and explain the score.

Git downloads a versioned copy of the source code. uv installs the Python packages it needs. A checkpoint contains the trained model parameters. Setup also downloads the human receptor reference needed to reconstruct chains from gene names. The commands are in the scoring tutorial.

The assistant may ask to run an installer or download model files. Review the proposed steps for your installation. Keep the computer awake during downloads and inference.

5. Check the saved result

Ask the assistant to open the output CSV and show the commands that produced it.

  • Files: find the script and output CSV at the reported paths.
  • Model: the score column is pll_DecoderTCR-ESMC_300M.
  • Reconstruction: read ok, tcr_reason and hla_reason before interpreting the score. Failed rows should remain in the CSV.
  • Interpretation: PLL ranks candidates in the supplied context. It is not a percentage chance of binding or a measured affinity.

Your score comes from your own run; this guide does not supply an expected numerical value. Continue to the scoring tutorial for interpretation, then try a small table of your own pairs.

If a step fails

Biohub is listed but not connected

Check the server address against the Biohub connection details above. Use your assistant’s MCP status command to read the connection error. Complete the specified sign-in, then start a new session. Institutional settings may restrict external servers.

The assistant cannot retrieve a model’s instructions

Ask it to show the Biohub resources or tools it can access and the retrieval error. Check the Biohub connection documentation. Do not substitute a remembered API for missing instructions; you can follow the site’s notebook directly.

The assistant cannot see my input file

Check that the file is inside the project folder opened by the assistant. A local session and a Colab notebook use different file systems. Follow the tutorial’s upload step when working in Colab.

The terminal says a command was not found

Reopen the terminal after installation and check again. Follow the official installer for your operating system. The MCP commands require the corresponding CLI; Codex and Claude Code desktop users can use the configuration options above.

Sign-in or university account errors

Use the provider’s account guide linked in step 2. Institutional access may require an administrator to enable the assistant or MCP connection. Assistant sign-in and Biohub server sign-in are separate.

A download fails or the model runs out of memory

Ask the assistant which download or process failed and whether the checkpoint is complete. For the local example, confirm the 300M checkpoint and CPU are selected. Keep the error and environment details; a lab workstation may be needed.

A Python package does not install

Ask the assistant to identify the package and check its supported platforms. If you move to a lab computer or Linux environment, open your project and configure the Biohub connection there too.

A row has no score

Read the reconstruction reason columns. Check the V/J gene names, CDR3 sequences and HLA allele. A missing score is not evidence that the pair does not bind.

For Gemini CLI installation permission errors, follow npm’s installation guide. For model or tutorial questions, the feedback page helps you prepare a question with the command, error and relevant input fields.
